* Why use seeded vertex order?

The already completed two-policy native coaffine survey of 511 exact third-iterate classes gave 420 positive coaffine weak-endomorphism maps, but 412 of those maps retract onto non-expansive targets. Eight positive maps (the two original branching policies on each of four graphs) established new K-divergences for original McKay 10481909, 10586728, 11438191 and 11578321; their exact full certificates are permanently preserved and independently verified in the preceding research directory.

The earlier public native solver =pycliques.find_coaffine_endomorphism= stops as soon as it finds *one* valid map. A source that retracts onto a simple four-cycle may also possess a different coaffine endomorphism with an expansive stable-image retract, but this need not be discovered by the first branching choice. A new implementation of the solver is unnecessary: the public API already permits control over source node iteration order and the existing =label= / =fiber= value policies.

This pilot uses *three explicitly deterministic seed permutations* per source and both public policies. The original graph is unchanged: only NetworkX node insertion order is altered before invoking the *same pinned native C++ backend*. No duplicate CSP logic is introduced.

* Exact finite-graph guarantee

For an original graph \(G\), let \(X=P_3(G)\) be its completely pared third iterate, labeled canonically by the existing historical proof machinery. Fix source McKay index \(i\) and seed \(s\in\{1,2,3\}\). Define the permutation \(\pi_{i,s}\) by applying the exact Python =random.Random((i << 8) ^ s).shuffle= algorithm to \((0,\ldots,|X|-1)\). Construct a NetworkX graph whose vertices are inserted in this order, but whose edges are *exactly* those of \(X\). The verifier records a SHA-256 fingerprint of the full permutation, and reconstructs the exact permutation independently.

The native solver's returned map is converted into its *original canonical vertex coordinates*, so its mathematical meaning is not influenced by the internal source iteration order. The independent verifier then rebuilds \(P_3(G)\) from original ten-vertex graph6, checks every source edge and every coaffine vertex condition, computes the exact eventual stable image \(Y\), proves that a positive power \(f^e\) is an ordinary retraction \(X\to Y\), and verifies all claimed expansive invariant coaffine join subgraphs using the Three Summands Theorem 3.6 and Connected Summand Theorem 4.6 of Larrión--Neumann-Lara--Pizaña, /On expansive graphs/ (European J. Combin. 30 (2009), 372--379).

The exact third-iterate P3 class index is reused from the preceding archived survey. Its 511 representatives cover 606 original stiff ten-vertex graphs; the remaining three oversized P3 classes and three original reconstruction resource limits are handled separately. The 430 ten-originals depending on Astra's three unresolved nine-vertex sources are deliberately excluded.

* Work budget and interpretation

Each of eight independent shards receives its exact immutable source subset. Every source undergoes three seed shuffles and two value policies, for *exactly 3066 independent solver invocations*. The budget per invocation is *150000 states or two seconds*, whichever comes first. Thus the full experiment is bounded and reproducible.

For each native =FOUND=, the original canonical coaffine map, complete stable-image analysis and any expansive join subgraph proof are archived in JSON and independently replayed on every original edge. A positive theorem propagates to all originals of its exact P3 isomorphism class, by the historical complete graph-level bijection. A FOUND map without an expansive retract is not a divergence theorem; =EXHAUSTED= and =LIMIT_REACHED= never prove clique convergence.
