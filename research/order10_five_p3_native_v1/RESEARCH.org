* Context and certified inputs

Let \(P_0(G)\) be complete dominated-vertex paring and \(P_{j+1}(G)=P(K(P_j(G)))\), where \(K(G)\) is the intersection graph of inclusion-maximal completes. The five original ten-vertex McKay graphs below remain indeterminate after the five direct octahedral \(P_3\)-retractions and one further class lift certified by census PR #100. * Research method and finite proof discipline

We use the existing public =pycliques.find_octahedral_retraction_coaffine= function, not a new graph-specific solver, at the exact merged monorepo PR #56 commit =e27649a6898b8c5b5bdbb4c6c64fd792672ae0ae=. Each of the five authenticated \(P_3\) graphs is tested with both =value_order="label"= and =value_order="fiber"=, each with exactly \(2{,}000{,}000\) search states and \(90\) seconds. The native C++ solver is built explicitly with the existing monorepo command. The exact runtime versions are pinned to the distributions recorded in the overhaul's =uv.lock= using the committed =constraints.txt=. The pilot additionally checks immutable Git blob hashes of seven installed Python and C++ solver files and records all resolved package versions in every search artifact. This verifies installed source code, not merely an environment variable claiming a revision. Different value orderings may find different positive maps; neither changes the soundness of a checked certificate.

A =FOUND= result must supply complete antipodal pairs and an ordinary graph retraction onto an induced \(O_d=\overline{dK_2}\), with \(d\ge3\). The independent census verifier checks the nonedges within antipodal pairs, all cross-pair edges, fixation of every target vertex, and the entire source edge set; only such a positive certificate establishes \(K\)-divergence. =EXHAUSTED= is a genuine exhaustive negative conclusion about this particular target family at depth three, not about \(K\)-behavior in general. =LIMIT_REACHED= is inconclusive and must never be interpreted as absence of a retraction.

* Certified new result: \(P_3(G_{11656793})\) retracts onto \(O_{11}\)

The label-first native search found an ordinary retraction \(r:P_3(G_{11656793})\to O_{11}\) after \(10643\) search states, where \(P_3(G_{11656793})\) has \(216\) vertices and \(19663\) edges. The complete map is archived in =positive_o11.json=, pinned by its immutable Git blob and by a separate SHA-256 checksum of all \(216\) uncompressed, little-endian integer images; it records eleven explicit antipodal pairs. The independent verifier =verify_positive.py= reconstructs the original third-iterate graph6, checks the complete induced \(O_{11}\), checks that the projection fixes every target vertex, and verifies all \(19663\) source edges. By the ordinary retraction theorem and \(K(O_d)\cong O_{2^{d-1}}\) for \(d\ge3\), the original ten-vertex graph McKay 11656793 is \(K\)-divergent.

The two-million-state alternative fiber-first search was inconclusive on this same graph. The contrast is a practical example of why search-order strategies matter in a complete-or-bounded CSP. No stronger conclusion about the four other unresolved originals follows from limited searches.

* Direct reproduction in Emacs Jupyter

Start Emacs from the =pycliques-census= root with the overhauled =pycliques-project= installed at the pinned merge commit and the native C++ solver explicitly built. Use =python -m pip install -c research/order10_five_p3_native_v1/constraints.txt ./path/to/pycliques-project/packages/pycliques= and then =python -m pycliques.octahedral_coaffine_native --build=. The Jupyter entry point validates actual installed source bytes and package versions before starting the search. The first block reconstructs the five authenticated \(P_3\) graphs and independently recomputes their complement sizes and triangle counts, without hardcoding graph6 codes.

#+begin_src jupyter-python
import networkx as nx
from research.order10_overcap_p3_coaffine_v1.pilot import source_catalog
from research.order10_five_p3_native_v1.search import REMAINING
hosts = source_catalog()
for original_index in REMAINING:
    third = nx.from_graph6_bytes(hosts[original_index]["p3_graph6"].encode("ascii"))
    complement = nx.complement(third)
    triangles = sum(nx.triangles(complement).values()) // 3
    print(original_index, (len(third), third.number_of_edges()), (complement.number_of_edges(), triangles))
#+end_src
